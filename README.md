# Lapka — оформление оригинального Karijama/Jack + новые функции (2026)

Основа проекта: [Karijama/Jack](https://github.com/Karijama/Jack). **Дизайн сохранён в стиле исходного сайта**:
- синяя навигационная панель `navbar-dark bg-primary` с брендом Lapka;
- большой синий заголовок, хлебные крошки, стандартный контейнер Bootstrap;
- главная страница со **старой табличной компоновкой**: «Дата создания / Заголовок / Содержание / Действия»;
- прежняя логика Bootstrap-форм: синяя шапка создания записи, жёлтая шапка редактирования;
- светлый четырёхколоночный подвал.

Новый пользовательский интерфейс из предыдущего варианта (розовый/карточный дизайн) **не используется**. Изменены функции и содержимое записей, а не общая стилистика.

## Новые функции

- **Поиск** по кличке, нечувствительный к регистру русского текста (`casefold`), и фильтрация по виду, городу, статусу, размеру.
- **Пагинация** таблицы, 10 записей на страницу.
- **Карточка животного** с полями вида, возраста, пола, прививок, стерилизации, фото и контакта.
- **Формы создания и изменения** животных в прежнем оформлении Jack. Удаление только через POST с CSRF-проверкой.
- **Приюты** (отношение один-ко-многим с животными) и отдельная таблица приютов.
- **REST API** для животных и приютов, защищённые операции записи через заголовок `X-API-Key`.
- SQLite + SQLAlchemy, возможность настройки PostgreSQL, тесты pytest, Docker и коллекция Postman.

## Запуск на Windows

1. Распакуйте ZIP полностью в новую папку, не смешивая файлы с прошлой версией.
2. В этой папке запустите `start_windows.bat`. При первом запуске скрипт попросит установить постоянный пароль и сохранит его в локальном файле `.env`. Повторно спрашивать не будет. Если `.env` уже существует, пароль будет загружен из него.
3. При необходимости загрузите **только вымышленные демонстрационные анкеты** командой `.\.venv\Scripts\python.exe scripts\seed_demo.py`.
4. Откройте в браузере **http://127.0.0.1:5000/**. Здесь отображается оригинальный табличный дизайн, а не JSON.

При ручном запуске в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:SECRET_KEY = 'replace-with-long-random-key'
$env:ADMIN_PASSWORD = 'choose-your-admin-password'
$env:LAPKA_API_KEY = 'choose-your-api-token'
.\.venv\Scripts\python.exe scripts/seed_demo.py
.\.venv\Scripts\python.exe app.py
```

Для создания и редактирования объявлений в интерфейсе используйте вход в правой части синей шапки и пароль из `ADMIN_PASSWORD`. Без него просмотр сайта доступен, изменение данных закрыто.


## Постоянный пароль и ошибка «ADMIN_PASSWORD не настроен»

В этой версии `app.py` **загружает `.env` автоматически** через `python-dotenv`.
При запуске `start_windows.bat` без настроенного пароля появляется приглашение создать его один раз; пароль и API-ключ сохраняются в `.env`, **не в `.env.example`**.

Если пароль был установлен вручную, проверьте файл `.env` рядом с `app.py`:

```dotenv
ADMIN_PASSWORD="ваш-пароль"
LAPKA_API_KEY="ваш-api-ключ"
SECRET_KEY="ваш-постоянный-длинный-ключ-сессий"
```

`ADMIN_PASSWORD` должен быть без пробелов в начале/конце, и пароль на странице `/login` должен совпадать буквально (с учётом регистра). Файл `.env` исключён из Git; не публикуйте его.
Переменные окружения Windows имеют приоритет перед `.env`. Если в `start_windows.bat` есть старые строки `set "ADMIN_PASSWORD=..."`, удалите их, чтобы использовался `.env`.

**Обязательно закройте старый сервер** перед запуском новой версии. Если порт 5000 занят другой копией сайта, браузер по-прежнему обращается к ней, даже если пароль правильно сохранён в другой папке.
Для восстановления доступа просто остановите сервер, отредактируйте `ADMIN_PASSWORD` в `.env` и перезапустите `start_windows.bat`. Базу данных удалять не нужно.

## Страницы

| Страница | Содержание |
| --- | --- |
| `/` | Главная со старой Bootstrap-таблицей и фильтрами |
| `/animals` | Каталог в таком же оформлении |
| `/animals/<id>` | Подробная анкета |

| `/login` | Вход администратора |

### Пример API

```bash
curl 'http://127.0.0.1:5000/api/animals?q=мур&species=cat&per_page=10&page=1'
curl -X POST 'http://127.0.0.1:5000/api/animals' \
 -H 'Content-Type: application/json' -H 'X-API-Key: YOUR_API_KEY' \
 -d '{"name":"Мурка","species":"cat","city":"Якутск"}'
```

## Тестирование

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

В среде подготовки пройдены 20/20 тестов **бизнес-логики SQLAlchemy**, и все Jinja2-шаблоны успешно проходят синтаксический разбор. HTTP-интеграционные тесты из `tests/test_web.py` требуют установленного Flask и выполняются в вашей среде после установки `requirements.txt`.

## Данные старого Jack

Исходный `database.db` из репозитория содержит таблицу `bd` с произвольными текстовыми постами; новая модель использует таблицы `animals` и `shelters` в `instance/lapka.db`. Поэтому старую базу проект **не удаляет и не преобразует автоматически**: у старых постов нет обязательных сведений о виде животного и городе. Старую базу можно хранить отдельно как резервную копию.

Изменения выполнены в локальной копии, исходный GitHub-репозиторий не менялся.
